# 视频生成与口型同步模块开发流程

## 功能定位

视频模块负责把确认后的静帧转换成动态视频。口型同步模块负责把确认后的角色对白音频和视频画面对齐，生成带口型的视频候选。

它解决两个问题：

- 普通镜头从静帧变成运动视频。
- 有对白的角色镜头可以进一步生成口型同步版本。

在进入本模块前，长对白应先经过[表演节拍与对白镜头拆分开发流程](19-表演节拍与对白镜头拆分开发流程.md)，把说话、反应和插入镜头拆开。这样口型同步只承担当前说话节拍，不让一条短视频镜头承载整段对白。

## 用户操作流程

1. 用户进入视频生成页。
2. 页面读取当前分镜、已确认静帧、视频候选和项目音频。
3. 用户选择运动模式、时长和模型。
4. 点击生成视频。
5. 后端创建视频生成任务，前端轮询进度。
6. 生成成功后用户确认主视频。
7. 如果分镜绑定角色且有确认对白音频，可以点击口型同步。
8. 口型同步成功后生成新的视频候选，并可自动确认。

## 限流与任务恢复

`video.mjs` 对视频任务创建做了限流。Agnes 默认每 60 秒最多创建 2 个视频任务，避免触发供应商限制。

视频输入图片如果是本地地址，会先上传或转换成供应商可访问的公网 URL。

服务重启后，`recoverGenerationJobs()` 和 `resumeQueuedGenerationJobs()` 会尝试恢复 queued/running 的任务。

## 异常处理

- 没有确认静帧：禁止生成视频。
- 没有角色绑定或音频：禁止口型同步。
- 音频角色和分镜角色不一致：阻止或提示。
- 供应商限流：等待或重试。
- 视频远程 URL 失效：确认时尝试本地化失败则报错。
- 口型同步任务失败：记录到 generation_jobs.error_text。

## 恢复候选人工复核的实现要点

恢复候选不能直接确认主版本，必须先完成自动技术检查、三张抽帧证据、画面复核、人物一致性复核和动作连续性复核。

页面保存的复核请求结构如下：

```json
{
  "decision": "rework",
  "checklist": {
    "visualReviewed": true,
    "characterConsistencyReviewed": true,
    "motionContinuityReviewed": true,
    "characterChecks": [
      {
        "characterId": 18,
        "decision": "matched",
        "note": "三张抽帧中的人物外貌和服装连续。"
      }
    ]
  },
  "note": "横版素材需要进入竖屏终剪。"
}
```

后端兼容从顶层 `characterChecks` 和 `checklist.characterChecks` 读取角色结论，并在保存前按恢复检查报告重新校验预期角色。这样可以避免页面字段结构与服务端规范化入口不一致，导致“已填写但无法落库”。

## 单条恢复候选竖屏终剪流程

恢复候选只有在技术检查通过、人工复核批准后，才允许创建单条终剪任务。终剪任务使用 `recovery-final-edit-v1` 标记，并保存源候选 ID、分镜 ID、幂等键和可回滚信息。

```text
video_assets.status = candidate
  -> 自动技术检查：ffprobe、COS 可读性、三张抽帧
  -> 人工复核：画面、动作、角色一致性
  -> POST /api/videos/:videoId/recovery-final-edit/execute
  -> export_records.status = queued
  -> Worker 只消费指定 exportId
  -> 读取当前数据库候选和确认音频
  -> buildSubtitleCuesFromAudioTracks()
  -> FFmpeg 生成 1080x1920 / 24fps / H.264 + AAC / 48000Hz / MP4
  -> COS 保存 final.mp4 与 subtitles.srt
  -> ffprobe 自动技术质检
  -> 人工终审和发布合规
```

### 字幕时序规则

恢复终剪不能把同一分镜的多条对白合并成一条覆盖全片的字幕。每条对白或旁白音频都要使用自己的 `startOffsetSeconds` 和 `durationSeconds` 生成独立 cue，并按说话人匹配分镜台词。

终剪 Worker 必须使用数据库实时重建的 `audioMix`、`subtitleCues` 和 `videoClips`。不能优先使用创建任务时保存的旧 `finalEditDraft`，否则会出现音频已分轨但 SRT 仍为旧整段字幕的问题。该边界由 `buildFinalEditRenderConfig()` 和回归测试保护。

## 市场质量代理审计与 10 条回归门禁

市场代理质检用于把“技术上可播放”和“可以进入人工发布审核”分开。它不是平台审核器，也不是人耳听感模型，更不能证明收入。

### 代理质检检查项

`server/services/market-quality-benchmark.mjs` 对每条真实导出执行以下硬门禁：

- 画面规格：`1080x1920 / 24fps / H.264 + AAC / MP4`。
- 音轨采样率：必须为 `48000Hz`。缺失、`44100Hz`、`96000Hz` 等都产生 `audio-sample-rate` 阻塞。
- 音频信号：必须可测量；检查 LUFS、True Peak、削波风险和对白活动覆盖。
- 字幕：检查 cue 是否存在、是否越界/重叠，以及字号和底部安全区。
- 对白同步：根据音频活动区间与字幕 cue 计算代理偏差；超过内部容差时阻塞。
- 开场节奏：记录首条对白和最长镜头，作为短视频节奏预警，不把预警当作审美结论。
- 平台证据：AI 标识、版权字段和目标平台规则备注必须完整，否则不能进入发布候选。

机器测量只提供可追溯信号。`ffprobe`、响度、波形、静音检测和抽帧都不能代替真人完整播放后的清晰度、响度平衡、爆音/失真与对白同步确认。

### 人工听感阻塞传播

`scripts/audit-market-quality.mjs` 从质量报告读取完整人工听感证据。只要没有保存 `approved` 且包含结构化音频证据，就生成：

```text
human-listening-required
```

`server/services/market-quality-audit.mjs` 会同时汇总：

- `audit.hardBlockers`
- `audit.humanBlockers`

这样项目级 `blockerCounts` 不会只统计机器阻塞而漏掉真人复核缺口；但它仍不会自动把人工缺口改成通过。

## Lip-sync 音频同源绑定与终剪门禁

口型同步的对白音频必须形成一条不可歧义的证据链：

```text
确认对白 audio_asset_id
  -> lip-sync 请求 audioAssetId
  -> video_assets.audio_asset_id
  -> 单条/项目终剪 syncAudioAssetId
  -> 终剪 dialogue 音轨 renderedDialogueAudioAssetId
```

终剪不得按“最新确认对白”或“同一分镜全部对白”模糊选择。`server/services/lip-sync-audio-binding.mjs` 负责：

- 对 `lip_sync` 视频强制要求绑定音频 ID；
- 校验绑定音频属于同一分镜且状态可用于终剪；
- 阻止绑定音频与终剪音频不一致；
- 过滤同一分镜的其它对白版本；
- 保留旁白独立音轨，不把旁白误当作人物对白源。

真实闭环记录：

- `export #59` 因单条视频 payload 遗漏绑定字段，被 `lip-sync-audio-source-missing` 阻断；
- 修复后 `video #198 -> export #60` 使用 `audio #170` 生成口型，也使用 `audio #170` 终剪混音，绑定证据 `sameSource=true`；
