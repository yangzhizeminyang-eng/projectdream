# 静帧生成与候选确认模块开发流程

## 功能定位

静帧生成模块负责把分镜的视觉提示词、角色约束和项目画幅比例转换成候选画面。静帧是视频生成的基础，确认后的主静帧会进入视频生成和成片编辑。

## 用户操作流程

1. 用户从分镜进入画面生成页。
2. 页面读取当前分镜、视觉提示词和角色一致性上下文。
3. 如果角色上下文不完整，页面提示阻塞原因。
4. 用户选择普通静帧、起始帧或结束帧。
5. 用户点击生成。
6. 后端创建生成任务。
7. 前端轮询任务进度。
8. 生成成功后进入结果页。
9. 用户从候选图中确认主版本。

## 前端开发流程

相关页面：

- `src/views/FrameGenerate.vue`
- `src/views/FrameResult.vue`

相关 API：

- `getStoryboard(storyboardId)`
- `getModelSettings()`
- `generateShotImages(storyboardId, payload)`
- `getGenerationJob(jobId)`
- `listShotImages(storyboardId)`
- `confirmImage(imageId)`

页面重点：

- `selectedFrameRole` 区分 `primary / start / end`。
- `frameCharacterContext.ready` 决定能否生成。

- 结果页按 frameRole 展示候选和确认状态。

## 后端开发流程

后端入口：

- `server/index.mjs`

服务：

- `server/services/frame.mjs`
- `server/services/frame-character-consistency.mjs`
- `server/services/ai/frame-prompt.mjs`

接口：

```text
POST /api/shots/:storyboardId/images/generate
GET  /api/shots/:storyboardId/images
POST /api/images/:imageId/confirm
GET  /api/generation-jobs/:jobId
```

生成任务流程：

```text
POST /api/shots/:storyboardId/images/generate
  -> authenticate
  -> 查询分镜和项目
  -> resolveFrameCharacterContext()
  -> 如果 ready=false，返回阻塞原因
  -> createGenerationJob(job_type='frame_image')
  -> queueGenerationJob()
  -> 返回 generation job

后台 processFrameGenerationJob()
  -> 读取 request_json
  -> buildFrameConsistencyPrompt()
  -> generateFrameCandidates()
  -> 校验图片比例
  -> 持久化到 .codex-runtime/generated-frames
  -> 写入 image_assets
  -> 更新 generation_jobs 成功或失败
```

确认图片流程：

```text
POST /api/images/:imageId/confirm
  -> authenticate
  -> 校验图片归属
  -> 同一 storyboard + frame_role 下其他图片改为 candidate/rejected
  -> 当前图片改为 confirmed
  -> 回写 storyboards.image_url 或 end_image_url
```

## AI 服务配置

`frame.mjs` 支持多个 provider：

- mock
- Agnes
- 火山方舟（Volcengine / Seedream）
- ToAPI
- BigModel / 智谱
- trae-url

关键配置来自环境变量和模型设置中心：

- `FRAME_PROVIDER`
- `FRAME_BASE_URL`
- `FRAME_API_KEY`
- `FRAME_MODEL`
- `FRAME_IMAGE_RATIO`
- `FRAME_WATERMARK_ENABLED`
- `FRAME_FALLBACK_MODELS`
- `FRAME_FALLBACK_TO_MOCK`

火山方舟接入约束：

- `FRAME_BASE_URL` 使用 `https://ark.cn-beijing.volces.com/api/v3`，代码会统一补齐 `/images/generations`，避免重复拼接。
- Seedream 4.5 的官方模型标识使用 `doubao-seedream-4-5-251128`；旧配置中的 `doubao-seedream-4.5-251128` 会在请求前归一化。
- 请求体使用 `model`、`prompt`、`size`、`response_format`、`watermark` 和可选 `image`，不能套用 ToAPI 的异步任务协议。
- 生成任务仍由 Worker 消费；API 只写入 `generation_jobs`，没有 Worker 时页面会保持 `queued`。

任务去重与 Worker 运行约束：

- `generation_jobs` 的活动任务复用不能只按 `project_id + job_type + source_id` 判断。
- 当 `job_type = frame_image` 时，还必须比较 `request_json.frameRole`，普通静帧、起始帧和结束帧不能互相复用。
- 其他生成类型仍可按同一来源复用活动任务，避免同一请求重复调用模型。
- 本地开发需要同时启动 API、前端和 Worker；只启动 API 时，接口可以成功创建任务，但任务会停留在 `queued`。
- 单条问题排查优先使用受控 Worker：设置 `GENERATION_WORKER_ONLY_JOB_ID` 与 `GENERATION_WORKER_MAX_JOBS=1`，验证完成后再退出，避免误消费其他队列或产生额外模型费用。

## 异常处理

- 可见角色没有绑定角色库：阻止生成。
- 可见角色缺性别或年龄：阻止生成。
- 可见角色没有确认参考图：阻止生成。
- 供应商返回图片比例不符合项目画幅：拒绝入库。
- 供应商错误或限流：根据重试和 fallback 配置处理。
- 生成任务失败：任务中心展示失败和错误信息。

## 上台讲解话术

```text
静帧模块不是简单把提示词发给图片模型。
在生成前，后端会先检查当前分镜里有哪些角色、是否绑定到角色库、是否有性别年龄和定妆参考图。
通过这些约束生成出来的图片才会更稳定。
生成结果不会直接覆盖分镜，而是先进入 image_assets 候选列表，由用户确认主版本后才回写到 storyboards。
```
