# 核心功能块总览与上台讲解顺序

## 一句话定位

ProjectDream 是一个把“故事想法”逐步生产成“可导出的 AI 漫剧短片”的项目级工作台。它的核心不是单次调用 AI，而是把文本、角色、分镜、图片、视频、音频、剪辑和导出串成一条可保存、可编辑、可追踪的生产链路。

## 推荐上台讲解顺序

1. 认证登录注册模块：说明系统有用户边界，数据按用户隔离。
2. 项目管理与总览模块：说明 `projectId` 是全链路主线。
3. AI 故事总纲生成模块：说明文本模型把创意变成结构化上游语境。
4. 场景拆解模块：说明总纲被拆成可执行的场景。
5. 单场景剧本模块：说明场景进一步变成对白、动作和情绪节奏。
6. 角色库与角色一致性模块：说明角色从普通文本变成有 ID 的固定实体。
7. 分镜生成与编辑模块：说明分镜是承上启下的核心中间层。
8. 静帧生成模块：说明分镜提示词如何变成候选画面。
9. 视频生成与口型同步模块：说明从静帧到动态视频，再到对白口型。
10. 音频生成与声线绑定模块：说明对白、旁白和角色声线如何绑定。
11. 任务中心模块：说明长耗时任务如何后台执行、轮询和恢复。
12. 资产库模块：说明所有生成结果如何统一追踪。
13. 成片编辑与时间线模块：说明视频轨和音频轨如何对齐。
14. 合成导出模块：说明最终用 FFmpeg 输出 MP4。
15. AI 模型设置中心：说明系统如何支持模型配置和供应商切换。

## 总体数据流

```text
用户登录
  -> 创建项目 projects
  -> 生成总纲 story_outlines
  -> 拆解场景 script_scenes
  -> 生成单场剧本 script_scenes.content
  -> 建立角色 characters
  -> 生成分镜 storyboards
  -> 生成静帧 image_assets
  -> 生成视频 video_assets
  -> 生成音频 audio_assets
  -> 保存剪辑草稿 final_edit_drafts
  -> 创建导出记录 export_records
```

## 核心设计思路

第一，所有业务都围绕项目展开。用户创建项目以后，项目 ID 会贯穿总纲、场景、角色、分镜、素材和导出记录。

第二，AI 输出不直接当最终结果。文本模型返回的总纲、场景、剧本、分镜都会经过结构化解析和数据库保存；图片、视频、音频也会进入候选列表，由用户确认主版本。

第三，长耗时任务不让页面卡死。图片、视频、口型同步和导出会写入任务表或运行状态，前端通过轮询看到队列、执行、成功、失败或取消。

第四，角色一致性被提前设计进链路。分镜生成静帧前会校验角色 ID、性别、年龄、参考图和角色描述，减少不同镜头里角色漂移。

第五，最终交付以成片为准。系统不止展示素材，而是把视频轨、音频轨、字幕和导出记录组织起来，最终生成 MP4。

## 现场讲解建议

先讲“为什么需要流程化”，再讲“怎么把流程落到代码里”。不要一开始就陷入模型 API 名称，可以先让评委知道这不是一个单点 Demo，而是一个完整生产系统。

推荐话术：

```text
这个项目的核心难点不是某一次 AI 生成，而是把多次生成结果组织成一个稳定的项目流程。
所以我把系统拆成项目、总纲、场景、剧本、角色、分镜、静帧、视频、音频、剪辑和导出这些模块。
每个模块既有自己的页面，也有自己的 API、数据表和异常处理。
这样用户可以一步一步推进，也可以在任何阶段人工修改和确认。
```
