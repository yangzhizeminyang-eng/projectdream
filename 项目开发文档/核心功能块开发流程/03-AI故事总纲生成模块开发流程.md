# AI 故事总纲生成模块开发流程

## 功能定位

故事总纲模块负责把用户创建项目时填写的题材、故事方向、视觉风格和目标时长，转换成结构化的故事蓝图。它是后续场景拆解、单场剧本、角色提取和分镜生成的上游语境。

## 用户操作流程

1. 用户进入 AI 剧本页。
2. 页面读取当前项目和最新总纲。
3. 用户点击生成总纲。
4. 后端调用文本模型生成结构化 JSON。
5. 后端规范化模型返回内容。
6. 写入 `story_outlines`。
7. 页面展示故事标题、logline、三幕结构和场景草案。
8. 用户可以继续生成正式场景。

## 前端开发流程

相关页面：

- `src/views/AIScript.vue`

相关 API：

- `getProject(projectId)`
- `getLatestOutline(projectId)`
- `generateOutline(projectId)`
- `listScenes(projectId)`
- `generateScenes(projectId)`
- `generateSceneScript(sceneId)`

页面状态主要分为：

- 项目加载中
- 总纲加载中
- 总纲生成中
- 场景生成中
- 错误提示
- 重新生成确认弹窗

重新生成总纲可能覆盖上游语境，所以前端会先弹确认，避免用户误操作。

## 后端开发流程

后端入口：

- `server/index.mjs`

AI 服务：

- `server/services/ai/outline.mjs`
- `server/services/ai/prompts/outline.mjs`
- `server/services/ai/provider.mjs`
- `server/services/ai/parsers.mjs`

接口：

```text
GET  /api/projects/:projectId/outline
POST /api/projects/:projectId/outline/generate
```

生成流程：

```text
POST /api/projects/:projectId/outline/generate
  -> authenticate
  -> 校验项目归属
  -> aiGenerateOutline(project)
  -> buildOutlinePrompts(project)
  -> generateStructuredJson()
  -> normalizeOutlinePayload()
  -> 计算 version_no
  -> 写入 story_outlines
  -> 更新项目 status
  -> 返回 OutlineDTO
```

`generateStructuredJson()` 会统一处理 OpenAI-compatible 接口调用、超时、鉴权、模型返回内容和 JSON 解析。

如果配置为 mock provider，或真实模型调用失败且允许 fallback，系统会生成 mock 总纲，保证本地演示流程能跑通。

## 数据表说明

核心表：

- `story_outlines`

关键字段：

- `project_id`：所属项目。
- `version_no`：总纲版本号。
- `title`：故事标题。
- `logline`：一句话故事。
- `premise`：故事前提。
- `summary`：总述。
- `act1_text / act2_text / act3_text`：三幕结构。
- `visual_style`：视觉风格。
- `raw_json`：模型原始结构化结果。

## 结构化解析

模型输出不能直接信任。后端会通过 `normalizeOutlinePayload()` 做兜底：

- 缺字段时使用项目基础信息补齐。
- 场景编号不合法时重新排序。
- 时长字段转为正整数。
- 空文本替换为安全占位。
- 原始 JSON 仍保留，方便追溯。

## 异常处理

- 项目不存在或不属于当前用户：拒绝。
- AI 未配置：走 mock 或返回配置错误。
- AI 返回非 JSON：抛出结构化解析错误。
- 生成失败：前端展示错误，不写入无效总纲。

## 上台讲解话术

```text
总纲模块是整个 AI 创作链路的第一步。
用户不是直接从一句话生成视频，而是先让文本模型生成一个结构化故事蓝图。
后端要求模型返回 JSON，然后经过 normalizeOutlinePayload 做清洗和兜底，再写入 story_outlines。
这样后面的场景、剧本和分镜都有稳定的上游语境，而不是每一步都重新猜故事。
```
