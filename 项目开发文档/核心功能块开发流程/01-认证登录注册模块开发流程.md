# 认证登录注册模块开发流程

## 功能定位

认证模块负责用户进入系统前的身份确认，包括手机号注册、密码登录、短信验证码登录、找回密码和重置密码。它的作用是给后续项目数据建立用户边界，保证不同用户只能访问自己的项目、素材和任务。

## 用户操作流程

1. 用户进入登录页。
2. 输入手机号和密码，或走短信验证码登录。
3. 后端校验用户、密码或验证码。
4. 校验成功后创建会话 token。
5. 前端把 token 和用户信息保存到 `localStorage`。
6. 路由守卫检测到登录态后，允许进入 `/dashboard` 和 `/workspace/*` 页面。
7. 用户退出登录时，前端清空本地 token 并跳回登录页。

## 前端开发流程

相关页面：

- `src/views/Login.vue`
- `src/views/Register.vue`
- `src/views/ForgotPassword.vue`
- `src/views/ResetPassword.vue`
- `src/components/BrandPanel.vue`

相关 API：

- `src/api/auth.ts`

关键函数：

- `loginWithPassword(phone, password)`
- `loginWithSms(phone, code)`
- `sendSmsCode(phone, type)`
- `registerWithSms(phone, code, nickname, password)`
- `resetPassword(phone, code, newPassword)`
- `checkPhone(phone)`
- `saveAuthSession(result)`
- `clearAuthSession()`
- `hasAuthSession()`

前端页面先做基本格式校验，例如手机号必须是 11 位、密码至少 6 位。提交后统一调用 `auth.ts`，由 `request()` 封装请求地址、JSON 请求头、响应解析和错误提示。

`auth.ts` 里还做了连接失败重试。后端刚启动时可能还没完全 ready，前端会按 `300ms、800ms、1500ms、2500ms、4000ms` 的节奏重试网络连接错误，避免用户一打开页面就遇到临时连接失败。

## 路由守卫流程

路由配置在 `src/router/index.ts`。

认证页使用：

```ts
meta: { guestOnly: true }
```

工作台页使用：

```ts
meta: { requiresAuth: true }
```

守卫逻辑：

```text
访问需要登录的页面
  -> 前端检查 localStorage 是否有 token
  -> 没有 token：跳回登录页
  -> 有 token：允许进入

访问登录/注册页
  -> 如果已经有 token
  -> 自动跳到项目总览页
```

注意：前端只负责体验层的拦截，真正安全边界在后端。后端每个业务接口都会通过 `Authorization` token 查用户。

## 后端开发流程

后端入口：

- `server/index.mjs`

关键表：

- `users`
- `sms_codes`
- `sessions`

核心函数：

- `normalizePhone(input)`：统一清洗手机号。
- `hashPassword(password)`：对密码做哈希。
- `createToken()`：创建会话 token。
- `sendVerificationCode(phone, type, code)`：调用短信服务或 mock。
- `consumeCode(phone, type, code)`：消费验证码，防止重复使用。
- `createSession(user)`：写入 sessions 表。
- `authenticate(req, res)`：从请求头读取 token 并查用户。

接口流程：

```text
POST /api/auth/register
  -> 校验手机号、验证码、昵称、密码
  -> 检查手机号是否已注册
  -> 消费验证码
  -> 写入 users
  -> 创建 sessions
  -> 返回 token + user

POST /api/auth/login-password
  -> 校验手机号和密码
  -> 查 users
  -> 比对 password_hash
  -> 创建 sessions
  -> 返回 token + user

POST /api/auth/send-code
  -> 校验手机号和类型
  -> 生成验证码
  -> 调用短信服务或 mock
  -> 写入 sms_codes
```

## 数据表说明

`users` 保存用户手机号、昵称、密码哈希。

`sms_codes` 保存短信验证码、验证码类型、过期时间、是否已使用。

`sessions` 保存 token、用户 ID、手机号和是否撤销。

## 异常处理

- 手机号格式不正确：前后端都拦截。
- 注册时手机号已存在：后端返回业务错误。
- 登录时用户不存在：返回账号或密码错误。
- 验证码过期、已使用、错误：后端拒绝。
- 短信服务未配置：可以走 mock provider，方便本地演示。
- token 不存在或无效：后端返回未授权。

## 上台讲解话术

```text
认证模块的重点不是页面表单，而是给整个项目系统建立用户边界。
前端通过 localStorage 保存 token 做路由拦截，后端通过 sessions 表做真正鉴权。
后续所有项目、分镜、素材和导出接口都会先 authenticate，确认当前用户只能操作自己的数据。
短信验证码也有单独的 sms_codes 表，支持过期、已使用和不同验证码类型。
```
