# 角色库与角色一致性模块开发流程

## 功能定位

角色库模块负责把剧本中的人物从普通文本变成可管理的角色实体。每个角色都有唯一 ID、名称、身份、性别、年龄段、外貌、性格、声线和定妆参考图。

角色一致性模块负责在静帧生成前校验分镜中的角色是否可识别、是否绑定到角色库、是否具备清晰性别年龄和参考图，从而减少 AI 生成时的人物漂移。

## 用户操作流程

1. 用户进入角色库。
2. 可以手动创建角色，也可以基于总纲和剧本一键生成角色档案。
3. 用户进入角色详情页，补充外貌、性格、年龄、性别和声线。
4. 可以生成角色定妆图候选。
5. 用户确认一张定妆图作为参考图。
6. 分镜编辑时绑定角色 ID。
7. 静帧生成前，系统校验角色上下文是否 ready。

核心接口：

```text
GET  /api/projects/:projectId/characters

POST /api/projects/:projectId/characters/generate
GET  /api/characters/:characterId
PUT  /api/characters/:characterId

GET  /api/characters/:characterId/images
POST /api/characters/:characterId/images/generate
POST /api/character-images/:imageId/confirm
POST /api/characters/:characterId/rename-preview
GET  /api/characters/:characterId/voice-recommendations
PUT  /api/characters/:characterId/voice-binding
```

AI 生成角色流程：

```text
POST /api/projects/:projectId/characters/generate
  -> authenticate
  -> 校验项目
  -> 读取总纲、场景、剧本
  -> aiGenerateCharacters()
  -> normalizeCharactersPayload()
  -> 去重并写入 characters
```

角色定妆图流程：

```text
POST /api/characters/:characterId/images/generate
  -> authenticate
  -> 校验角色归属
  -> 检查 appearance 是否为空
  -> 创建 generation_jobs
  -> 后台调用 generateCharacterImageCandidates()
  -> 写入 character_images
```

角色一致性校验流程：

```text
FrameGenerate 页面读取 storyboard
  -> 后端 storyboardRow() 组装 frameCharacterContext
  -> resolveFrameCharacterContext(storyboard, characters)
  -> 检查角色是否匹配、是否视觉出现、是否有性别年龄、是否有参考图
  -> ready=false 时阻止静帧生成
```

## 数据表说明

核心表：

- `characters`
- `character_images`
- `storyboards`
- `image_assets`

关键字段：

- `characters.id`：角色唯一 ID。
- `characters.name`：角色名。
- `characters.gender / age_group`：性别和年龄段。
- `characters.appearance`：固定外貌。
- `characters.reference_image_url`：确认后的定妆参考图。
- `characters.voice_profile_key`：绑定声线。
- `characters.voice_locked`：声线是否锁定。
- `character_images.status`：candidate 或 confirmed。
- `image_assets.character_snapshot`：静帧生成时的角色约束快照。

## 角色改名同步

角色改名不是简单更新 `characters.name`。如果用户选择同步引用，后端会生成改名计划并事务更新：

- 项目描述。
- 总纲 JSON。
- 场景文本。
- 分镜动作、对白和视觉提示词。

这样可以避免角色名称在不同模块里前后不一致。

## 异常处理

- 角色名为空或重复：拒绝。
- 年龄段、性别非法：拒绝。
- 角色外貌为空：禁止生成定妆图。
- 可见角色没有参考图：静帧生成阻塞。
- 分镜里出现人类主体但无法匹配角色库：静帧生成阻塞。
- 改名影响历史媒体素材：前端提示用户旧素材不会自动重绘。

## 上台讲解话术

```text
角色库是保证漫剧连续性的关键模块。
如果只在提示词里写角色名，AI 很容易每个镜头都画成不同的人。
所以我把角色做成数据库实体，每个角色有 ID、性别、年龄、外貌和定妆参考图。
静帧生成前还会做角色一致性校验，只有角色信息完整、参考图确认后，才允许生成包含人物的镜头。
```
