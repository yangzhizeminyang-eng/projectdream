# 分镜生成与分镜编辑模块开发流程

## 功能定位

分镜模块是系统最关键的中间层。它承接单场剧本，向下决定静帧、视频、音频、字幕和成片时间线。

每条分镜包含镜头编号、景别、机位、构图、时长、角色绑定、动作、对白、视觉提示词、起始帧提示词和结束帧提示词。

## 用户操作流程

1. 用户在剧本编辑页点击生成分镜。
2. 后端读取当前场景剧本并调用文本模型拆镜。
3. 生成的分镜写入 `storyboards`。
4. 用户进入分镜看板查看全部镜头。
5. 用户进入分镜编辑页，修改动作、对白、角色、时长和视觉提示词。
6. 用户可以使用导演关键帧工具优化起始帧和结束帧。
7. 用户可以拆分长动作或多人对白。
8. 确认后进入静帧生成。

分镜编辑页的重点是上下文稳定：

- 通过 URL query 读取 `projectId / sceneId / storyboardId`。

- 切换分镜前检测是否有未保存改动。

## 后端开发流程

后端入口：

- `server/index.mjs`

AI 服务：

- `server/services/ai/storyboard.mjs`
- `server/services/ai/prompts/storyboard.mjs`
- `server/services/ai/frame-prompt.mjs`
- `server/services/ai/parsers.mjs`

接口：

```text
GET  /api/scenes/:sceneId/storyboards
POST /api/scenes/:sceneId/storyboards/generate
GET  /api/storyboards/:storyboardId
PUT  /api/storyboards/:storyboardId
POST /api/storyboards/reorder
POST /api/storyboards/:storyboardId/frame-prompt/rewrite
POST /api/storyboards/:storyboardId/keyframes/optimize
POST /api/storyboards/:storyboardId/continuity/start-frame
POST /api/storyboards/:storyboardId/split
POST /api/storyboards/:storyboardId/dialogue/split
```

生成分镜流程：

```text
POST /api/scenes/:sceneId/storyboards/generate
  -> authenticate
  -> 校验场景归属
  -> 检查 scene.content 不为空
  -> 读取项目和角色库
  -> aiGenerateStoryboards()
  -> normalizeStoryboardPayload()
  -> 根据角色名匹配 character_id
  -> 写入 storyboards
  -> 更新项目 status
```

编辑分镜流程：

```text
PUT /api/storyboards/:storyboardId
  -> authenticate
  -> 校验分镜归属
  -> 如果传 characterId，检查角色是否属于同项目
  -> 更新允许字段
  -> 返回 StoryboardDTO + frameCharacterContext
```

## 导演关键帧

导演关键帧用于动作镜头：

- 起始帧：动作开始前的人物姿态和构图。
- 结束帧：动作完成后的状态和空间位置。

后端 `optimizeStoryboardKeyframes()` 会读取当前分镜、相邻分镜、角色库和视觉风格，生成更适合两帧模式的提示词。

`copyPreviousFrameToStoryboard()` 可以把上一镜头的确认画面作为当前起始帧，减少镜头之间人物跳变。

## 拆分能力

`splitStoryboard()`：把长动作拆成 2 到 4 个短分镜。

`splitStoryboardDialogue()`：把多人对白拆成多个单说话人分镜，便于后续音频和口型同步。

拆分前会检查当前分镜是否已经有生成素材。如果已经有图片、视频或音频，默认不允许拆分，避免破坏已确认结果。

## 异常处理

- 空剧本禁止生成分镜。
- 分镜绑定角色时，角色必须属于当前项目。
- 拆分已有素材的分镜会被阻止。
- 多人对白拆分时，如果无法识别多个说话人，会返回提示。
- 保存后如果上下文已切换，前端丢弃旧结果。
