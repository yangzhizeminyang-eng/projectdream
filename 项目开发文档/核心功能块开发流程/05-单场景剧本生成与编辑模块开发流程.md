# 单场景剧本生成与编辑模块开发流程

## 功能定位

单场景剧本模块负责把一个场景扩展成完整剧本文本，包括人物对白、动作、环境氛围和节奏说明。它是分镜生成的直接输入。

## 用户操作流程

1. 用户从场景列表进入剧本编辑页。
2. 页面读取项目、场景列表和当前场景详情。
3. 用户点击生成剧本。
4. 后端基于项目、总纲和当前场景调用文本模型。
5. 生成内容写回 `script_scenes.content`。
6. 用户可以人工编辑剧本、保存。
7. 用户点击生成分镜，进入分镜看板。

## 前端开发流程

相关页面：

- `src/views/ScriptEditor.vue`

相关 API：

- `getProject(projectId)`
- `listScenes(projectId)`
- `getScene(sceneId)`
- `generateSceneScript(sceneId)`
- `saveSceneScript(sceneId, payload)`
- `generateStoryboards(sceneId)`

页面要处理两个重要状态：

- 剧本文本草稿是否和数据库一致。
- 切换场景时是否丢弃未保存内容。

当用户点击“生成分镜”时，前端会先调用 `generateStoryboards(sceneId)`，成功后跳转到：

```text
/workspace/storyboard?projectId=xxx&sceneId=xxx
```

## 后端开发流程

后端入口：

- `server/index.mjs`

AI 服务：

- `server/services/ai/script.mjs`
- `server/services/ai/prompts/script.mjs`
- `server/services/ai/provider.mjs`
- `server/services/ai/parsers.mjs`

接口：

```text
GET  /api/scenes/:sceneId/script
POST /api/scenes/:sceneId/script/generate
PUT  /api/scenes/:sceneId/script
```

生成流程：

```text
POST /api/scenes/:sceneId/script/generate
  -> authenticate
  -> 查询场景并校验 owner
  -> 查询项目和最新总纲
  -> aiGenerateSceneScript()
  -> buildSceneScriptPrompts()
  -> generateStructuredJson()
  -> normalizeSceneScriptPayload()
  -> 更新 script_scenes.content / mood / status
  -> 返回 SceneDTO
```

保存流程：

```text
PUT /api/scenes/:sceneId/script
  -> authenticate
  -> 校验场景归属
  -> 更新 title、content、mood 等字段
  -> 返回更新后的场景
```

## 数据表说明

核心表：

- `script_scenes`

关键字段：

- `content`：单场剧本文本。
- `mood`：情绪和氛围。
- `status`：剧本阶段状态。
- `updated_at`：最后编辑时间。

分镜生成时会读取：

- `script_scenes.content`
- `characters`
- `projects.visual_style`

## 结构化解析

模型生成剧本时，后端会要求返回结构化内容，再由 `normalizeSceneScriptPayload()` 清洗。这样可以把模型返回的正文、氛围、标题等字段稳定写回数据库。

## 异常处理

- 场景不存在或不属于当前用户：拒绝。
- 场景没有内容时，分镜生成会被后端阻止。
- AI 失败时，根据配置决定是否 fallback 到 mock。
- 切换场景前有未保存内容：前端弹出确认。

## 上台讲解话术

```text
单场景剧本模块是从“场景摘要”到“可拍剧本”的过渡。
模型不会直接生成视频，而是先生成一场完整剧本，包括对白、动作和氛围。
这段剧本文本会保存到 script_scenes.content，后续分镜生成就是基于这里的内容拆镜。
所以这个模块保证了镜头不是凭空生成，而是从剧本一步步推导出来。
```
