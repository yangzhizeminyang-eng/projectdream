### 0.1 本次查证最重要的负向结论

**剪映官方帮助中心在本次环境下整站不可达**，这一点已被逐一验证：

- `https://www.capcut.com/help/**`（含 `/interface-and-settings`、`/keyboard-shortcuts` 及 zh-tw / en-us / cs-cz 等语言版本）一律 **302 跨域重定向** 到 `https://www.capcut.cn`，抓取工具不跟随跨域跳转；
- `https://www.capcut.cn/help`、`/help-center`、`/helpcenter`、`/support`、`/tutorial` 全部 **404**；
- `help.capcut.com` 域名 **不存在**；官网页脚里的 `lv.ulikecam.com` 同样 302 回 capcut.cn；
- `https://www.capcut.cn/readme`（配置页）与 `https://www.capcut.cn/learning`（创作课堂）返回 200，但正文为纯前端渲染，抓不到文字。

因此本文能达到 `[官方]` 等级的，**只有剪映官网首页 `https://www.capcut.cn/` 的产品级描述**（例如「多时间线：在一个草稿里创建多条时间线，新增上限可达 50 条」「蒙版：支持线性、圆形、文字、钢笔等多种形式」），**没有任何一条界面尺寸、像素、毫秒级规格来自官方文档**。

### 0.2 检索工具限制（影响覆盖度）

- `web_search` 在本次调研进行到中途后持续返回 `HTTP 402 Insufficient Balance`（搜索端点余额不足，属环境配置问题，需在「设置 > 插件 > Web search」更换端点或充值），后续只能改用 `web_fetch` 直连；
- 直连时 知乎 403、B 站 opus 返回验证码页、百度/360/搜狗 结果页为前端渲染；
- 7 个方向的并行查证中，有 1 个方向（播放头渲染细节）因检索失败未产出，该节由我本人用 `web_fetch` 补齐，**渲染部分基本只能给工程推断**。

> **给后续维护者的建议**：官方帮助中心在正常国际网络下可访问，建议在有网络条件的机器上补核 CapCut Help Center 的 *Interface and settings / Preview / Proxy / Keyboard shortcuts* 四篇，把本文 `[教程]` 级结论升级为 `[官方]`。

### 0.3 本次研究同时盘点了自研工作台的现状（只读，未改任何源码）

用于对照与建议落地，事实来源是 `src/views/FinalEdit.vue` 与 `src/api/project.ts`（**行号会随正在进行的开发漂移，本文只按区块名引用**）：

- **瓦片布局**：`.final-edit-content` 用 `grid-template-areas: "materials player inspector" / "timeline timeline timeline"`；列宽 `minmax(300px, 360px) minmax(520px, 1fr) minmax(288px, 340px)`；行高 `minmax(var(--fe-preview-min-height, 380px), 1fr) minmax(180px, var(--fe-timeline-height, 22vh))`；`gap: 12px`。
- **时间线高度**：JS 变量 `timelineDockHeight` 默认 **200px**，拖拽钳制在 **180–620px**；已有 `fe-timeline-resize-handle`。
- **时间线缩放**：`timelinePixelsPerSecond` 范围 **36–220**，基准 72 px/s = 100%；轨道左侧标签列宽固定 **122px**。
- **播放头**：`timelinePlayheadStyle` 使用 **`left: ${122 + t * pps}px`**（改 `left`，触发布局，是本报告第 7 节重点）。
- **悬浮提示**：全文件仅 **7 处** 原生 `title="..."` 属性，没有自定义 tooltip 组件。
- **草稿模型**：`FinalEditDraftDTO.videoClips` 为**单一数组**（`clipId / storyboardId / order / enabled / videoAssetId / trimStartSeconds / trimEndSeconds / transition`），**没有轨道号、没有变换参数、没有叠加轨**——即目前**不具备画中画能力**；另有 `audioMix`（dialogue / narration / music / sfx 四路）与 `audioClips`、`subtitleCues`、`beatMarkers`、`emotionCurve`、`versionHistory`。
- **时间线轨道数**：界面描述为 `audioGroups.length + 2` 条轨道。

## 1. 整体布局与尺寸比例

### 1.1 剪映怎么做的

**（1）分区口径：官方没有给「四区」这个说法，教程普遍用 5 区。** `[教程]`
多本桌面版教材把剪辑界面拆成 **菜单栏 / 媒体素材区 / 播放器区 / 属性调节区 / 时间线区** 五块（詹泽鑫《剪映：从零开始精通短视频剪辑（电脑版）》第 2 章），另有教材拆成 6 区（多了「常用功能区」）或 7 区（多了「时间轴设置区」）。做四区复刻时，正确基准是：**上排三段式「素材区 ｜ 播放器 ｜ 属性面板」＋ 底部整宽时间线 ＋ 顶部菜单栏**。
来源：[book.qq.com/53899220/18](https://book.qq.com/book-read/53899220/18)、[xiaoshuo.qq.com/1048826993/10](https://xiaoshuo.qq.com/read/1048826993/10)

**（2）属性面板在右上角，不是最右侧全部。** `[教程]`
「属性调节区界面如图 1-95 右上角红框内所示」——属性面板贴在**播放器右侧、上排位置**；媒体素材区在**左上角**。也就是说「预览区在最右上」的说法不准确，最右上角是属性面板。
来源：[book.qq.com/53899220/18](https://book.qq.com/book-read/53899220/18)

**（3）剪映有预设布局模式，这是它比手动拖分隔线更常用的入口。** `[教程]`
菜单栏 →「布局调整」提供 **4 个单选项 + 一个还原按钮**：
- 媒体素材优先、播放器优先、属性调节优先、时间线优先；
- 被设为「优先」的区域**会变成一个独立窗口**，可拖动该窗口边框改大小；
- 想恢复默认，点「还原」。
**不存在** Premiere 那种可命名保存的多套工作区（两本独立教材均只记载这 5 项）。
来源：[xiaoshuo.qq.com/1048826993/11](https://xiaoshuo.qq.com/read/1048826993/11)、[book.qq.com/53899220/15](https://book.qq.com/book-read/53899220/15)

**（4）面板可拖拽调整是有的，但上下限无公开数值。** `[教程]` + `[推断]`
教材原话只有「将鼠标放在任意区域边界，拖动即可调整大小」「我们可以拖动窗口的边框来调整窗口的大小」，**没有任何像素上下限、最小宽度、默认比例**。
来源：[blog.csdn.net/u013741272/157945428](https://blog.csdn.net/u013741272/article/details/157945428)、[book.qq.com/53899220/15](https://book.qq.com/book-read/53899220/15)

**（5）时间线是面积最大的一块，但没有「占屏高 X%」的数据。** `[教程]`
原文只有相对关系：「其中占据面积最大的是时间轴，该区域也是剪映专业版中视频剪辑的主要区域」。
来源：[book.qq.com/55060327/14](https://book.qq.com/book-read/55060327/14)

**（6）1920×1080 下四区的真实像素值：`未查到确切数值`。** 
我逐一核查了可访问的官方页面与全部教程来源，**四个区的像素宽高一个都没有公开数值**。官方只给出显示器分辨率要求：**最低 1280×800，推荐 1920×1080 或更大**（该配置表参考来源标注为剪映专业版官网，我未能直接读到官网正文，属 `[教程]` 转引，出处 [夸克百科词条](https://baike.quark.cn/baike?id=68094b60e7c849ababd15daf0e3e1b3e)）。
→ **可执行做法：把 1920×1080 作为基准分辨率是合规的（官方推荐值），但四区像素比例必须实机量取。量取 SOP 见 1.3。**

**（7）一个真正可执行的「腾高度」杠杆：`Alt+K` 收起关键帧面板。** `[教程]`
在素材上右键 →「显示关键帧动画」（组合键 `Alt+K`）会占掉轨道空间，再按一次收起即可「减少轨道占用的空间」。只有图片/视频/文字有关键帧面板，音频没有。
来源：[zhihu.com/tardis/bd/art/902913917](https://www.zhihu.com/tardis/bd/art/902913917)

**（8）时间线区内部的固定分区。** `[教程]`
左上角是「选择和快捷功能区」，左侧有缩放滑块（左右两个放大镜图标）；下方是轨道控制区（轨道类型 / 锁定 / 隐藏 / 关闭原声）；最上方是时间轴刻度。四个开关的**默认值**：主轨磁吸=**开**、自动吸附=**开**、联动=**开**、预览轴=**关**。
来源：[book.qq.com/53899220/19](https://book.qq.com/book-read/53899220/19)

### 1.2 对自研工作台的可执行建议

1. **把「布局」做成和剪映同构的 4 个预设 + 还原**（改动最小、收益最高）：
   - 顶部工具条加一个 `layout` 图标按钮，下拉四项：`素材优先`、`预览优先`、`属性优先`、`时间线优先`；每项只改 `grid-template-columns` / `grid-template-rows` 的值，不写独立窗口（Web 里"独立窗口"成本高、收益低，用整列/整行扩展代替即可）；
   - 加「还原」按钮恢复 `"materials player inspector" / "timeline timeline timeline"` 默认值。
   - 建议预设值（1920×1080 基准，`[推断]`，可直接落到 CSS）：
     | 预设 | columns | 时间线行高 |
     |---|---|---|
     | 默认 | `minmax(320px, 360px) minmax(520px, 1fr) minmax(288px, 340px)` | `max(200px, 26vh)` |
     | 素材优先 | `minmax(400px, 520px) minmax(420px, 1fr) minmax(280px, 320px)` | `max(180px, 22vh)` |
     | 预览优先 | `minmax(240px, 280px) minmax(720px, 1fr) minmax(280px, 320px)` | `max(160px, 18vh)` |
     | 属性优先 | `minmax(240px, 280px) minmax(420px, 1fr) minmax(400px, 480px)` | `max(180px, 22vh)` |
     | 时间线优先 | `minmax(240px, 280px) minmax(480px, 1fr) minmax(280px, 320px)` | `max(420px, 45vh)` |
2. **时间线高度默认值偏小**。当前默认 `200px`、`--fe-timeline-height` 回退 `22vh`。1920×1080 下 200px 只有屏高 **18.5%**，而剪映的时间线是面积最大的区域。建议默认提到 `max(240px, 26vh)`（≈281px / 26%），钳制区间保留 `180–620px`，并让用户拖拽结果**持久化到 localStorage / 草稿 DTO**（剪映不持久化布局，但 Web 端用户更需要）。
3. **三列都要有拖拽手柄与上下限**。目前只有时间线有 `fe-timeline-resize-handle`。建议给素材区右边缘、属性面板左边缘各加一个 `role="separator"` 手柄，上下限：素材区 `240–520px`、属性面板 `280–480px`、预览列保底 `420px`（沿用你现在的注释思路「时间线可以往上提，但不能把预览压没」）。
4. **护住预览列最小值**：`--fe-preview-min-height: 380px` 保留，但在 1366×768（低于官方最低 1280×800 的高度）下必须提供「时间线优先」横向滚动兜底，否则轨道会被压到不可用。

### 1.3 四区像素比例的实机量取 SOP（30 分钟可完成，供后续把 `[推断]` 升级为实测）

1. 显示器设原生 1920×1080、Windows 缩放 100%，剪映专业版窗口最大化并进入草稿；
2. 截图（`Win + Shift + S` 全屏）；
3. 用任意取色/测量工具（或把截图拖进 Figma / 用 PowerShell + System.Drawing）量四个边界：素材区右边界 x₁、属性面板左边界 x₂、时间线顶部 y₁；
4. 换算：素材区宽 = x₁ − 左边缘；属性面板宽 = 右边缘 − x₂；时间线上高占比 = (1080 − y₁) / 1080；
5. **务必在 125% / 150% 缩放下再量一次**——笔记本上剪映的实际可用宽度会明显小于标称值，这是目前所有教程都没覆盖的坑。

### 2.2 对自研工作台的可执行建议

现状：`.fe-library-grid` 是 `1fr 1fr` 两列，卡片 `.fe-library-item` 是 `padding: 12px` 的普通块，`binQuery` 已有搜索，`activeMaterialPanel` 有 `media / audio / text / transitions` 四个面板，`editableVideoClips.length` 已显示"X 个镜头"。

1. **把素材卡补成剪映同构的信息结构**（这是本节最高收益项）：
   - 卡片固定尺寸 **150×118px**（缩略图 **150×84px = 16:9** + 名称 1 行 + 元信息 1 行）；两列网格在 360px 素材区内刚好放下（150×2 + 12 gap + 24 padding = 336px）；
   - **时长徽标**：缩略图**右下角**，格式 `mm:ss`（≥1 小时用 `h:mm:ss`），14px/600 字重、`background: rgba(0,0,0,.72)`、`border-radius: 4px`、`padding: 1px 5px`；**hover 时上移到右下角上方 26px**，把位置让给「+」按钮（避免同角位叠加冲突）；
   - **hover 行为**：`transform: translateY(-2px)` + 边框变 `var(--fe-accent)` + 右下角出现「+ 添加到时间线」按钮（`aria-label="添加到时间线"`），点击 = 追加到 `videoClips` 末尾；
   - **「已入轨」标记** `[推断，剪映没有]`：因为你的 `videoClips` 带 `storyboardId`，可以直接用 `new Set(editableVideoClips.map(c => c.storyboardId))` 算出「已加入」，在缩略图**左上角**画一条 3px 强调色竖条 + 一行 11px 文案「已入轨」。**这是你的非破坏式草稿模型天然能提供、而剪映没有的能力，建议保留但视觉上比 hover 按钮弱一档**，避免喧宾夺主。
2. **补齐剪映的 4 个管理图标**：搜索（已有）→ 增加**排序下拉**（5 个字段照抄：导入时间 / 名称 / 时长 / 文件类型 / 分镜号，其中「分镜号」替换剪映的"创建时间"，更贴合漫剧语境）、**类型筛选**（视频 / 图片 / 音频 / 全部）、**网格↔列表切换**（列表行高 36px，列：序号、缩略图 64×36、分镜号、时长、入轨状态）。
3. **性能与可读性**（回应"为什么它的可读性好"）：剪映的做法是**等高定宽卡片 + 统一 16:9 缩略图帧 + 常驻单一信息（时长）+ hover 才出现的动作按钮**，信息密度高但不打架。落到实现上：
   - 缩略图统一 `aspect-ratio: 16/9; object-fit: cover`，竖屏分镜用 `object-fit: contain` + 深色底，避免网格错行；
   - 卡片文字统一 `font-size: 12px; line-height: 1.35; -webkit-line-clamp: 1`，**不要换行撑高卡片**（行高漂移是网格可读性最大的杀手）；
   - 超过 200 张时启用虚拟滚动（`content-visibility: auto` + `contain-intrinsic-size: 150px 118px` 即可，不必引入虚拟列表库）。

3. **补全屏与快捷键**（一套自洽的键位，写进 UI 与文档，避免和浏览器冲突）：
   - `空格` 播放/暂停（**必须** `preventDefault`，否则页面滚动）；
   - `←` / `→` 逐帧（步长 = `1 / fps`，fps 从项目配置取，缺省 30 → 33.3ms）；
   - `Shift + ←` / `Shift + →` 逐秒；
   - `↑` / `↓` 上一 / 下一分割点（分割点集合 = 各 clip 的时间边界 ∪ `beatMarkers`）；
   - `J / K / L`：**建议做**（虽然中文剪映内置表未收录，但它是剪辑用户的肌肉记忆），标注为"自研扩展"，`K` = 暂停、`J`/`L` = 变速倒放/正放（连续按切换 1×/2×/4×）；
   - `~` 或 `F` 全屏（`~` 与剪映一致，但需在 `keydown` 里判断没有输入框聚焦）；
   - `Ctrl + B` 分割（你已有 `splitSelectedClip`），`Ctrl + Z / Ctrl + Shift + Z` 撤销重做（你已有 undo/redo 栈），`Tab` 切换素材面板。
4. **时码显示对齐剪映语义**：左侧当前时间（强调色）+ `/` + 总时长（次要色），并显示帧号（`00:12:03:14`），拖动播放头时**时码要跟着走**（当前 `formatTimecode(timelinePositionSeconds)` 已具备，注意拖动中节流到 rAF）。
5. **无障碍与状态**：无片段时禁用播放/全屏并给出 `aria-disabled` + 一句灰字原因（剪映是无提示置灰，**建议比剪映更好**：禁用态也给 tooltip，见第 5 节）。

### 4.2 对自研工作台的可执行建议

现状是**巨大的结构性优势**：你的 `videoClips` 是带 `order` 的有序数组，**主轨天然无"覆盖"问题**——插入即"在 order 序列中插入一项并重排后续 order"，不存在像素级覆盖。建议：

1. **实现统一的"拖拽载荷"协议**：
   ```ts
   type DragPayload =
     | { kind: 'storyboard'; storyboardId: number; durationSeconds: number }
     | { kind: 'audio'; audioId: number; track: 'dialogue'|'narration'|'music'|'sfx'; durationSeconds: number }
     | { kind: 'subtitle'; cueId: string }
   ```
   HTML5 DnD 的 `dataTransfer` 在 Vue 里够用，但**时间线内部拖动建议改用 Pointer Events**（`pointerdown → setPointerCapture`），因为需要连续计算落点 x 与吸附，`dragover` 的节流会掉帧。
2. **落点指示三件套**（比剪映多一件，但都低成本）：
   - **插入位竖线**：主轨插入时画 2px 强调色竖线（剪映用绿色；建议沿用你的 `var(--fe-accent)` 以统一视觉），位置 = 吸附后的落点；
   - **幽灵卡片**：半透明 60% 的片段块（宽 = `duration × pps`），跟随指针；
   - **时间码气泡**：指针上方 22px 处显示 `mm:ss:ff`，拖动中实时更新——这是剪映疑似有但查不到证据的交互，**建议做，因为对"漫剧按秒对齐台词"的价值极高**。
3. **吸附规则（建议值，`[推断]`，剪映未公开阈值）**：阈值 **8 CSS px**（换算成秒 = `8 / pps`，注意阈值必须定义在**屏幕像素域**而不是时间域，否则缩放后手感会变）。吸附目标按优先级：
   `① 已有片段边界（clip.start / clip.end） → ② subtitleCues 边界 → ③ beatMarkers（节拍点，漫剧卡点最关键） → ④ 播放头 → ⑤ 0 秒`。
   命中时竖线变色 + 显示目标标签（如「吸附：分镜 12 结尾 / 节拍 00:14」）。
4. **插入 vs 覆盖的语义选择（明确建议）**：
   - **默认 = 插入（Ripple Insert）**：落点在某片段中间时，把该片段在落点处**逻辑分割**或整体右移。因为你的模型是 `order` 数组 + `trimStart/trimEnd`，最干净的做法是**不真分割**，而是把新 clip 插到该位置并让后续 `order` 递增（渲染层按 order 顺序拼接），这与你现有的"非破坏式"设计完全一致；
   - **覆盖（Overwrite）= 按住 `Alt` 拖入**：替换落点区间内的整个 clip（把被覆盖 clip 的 `enabled` 置 false 并写入 `versionHistory`，而不是删除），这样可一键回滚；
   - **两个模式都要在落点竖线旁给出文字提示**（「插入 3 个片段之后」/「覆盖 分镜 12」）——剪映恰恰是在这一点上"无声且不确定"，**这是自研可以明确超越的地方**。
5. **按类型限制落点轨道（照抄剪映并收敛）**：
   - 音频类（dialogue / narration / music / sfx）**只允许落在对应音轨行**，拖到视频区时整行高亮并显示禁用光标（`cursor: not-allowed` + 拖拽幽灵变灰），而不是"松手后自动弹回"——比剪映的"自动移回"更可预期；
   - 字幕 cue 只允许落在字幕轨；
   - 视频/图片默认落主轨；按住 `Shift` 拖入第 2 条视频轨 = 创建画中画（见第 6 节）。
6. **素材区点「+」= 按播放头插入**（与剪映一致）：把 `+` 绑定到"在 `timelinePositionSeconds` 处插入"，而不是简单 `push` 到末尾。这是最容易被忽略但最影响"感觉对不对"的一条。

### 5.2 对自研工作台的可执行建议

现状：**全文件只有 7 处原生 `title="..."`**。原生 `title` 的问题很明确：延迟约 1–2 秒（不可控）、样式不可控、`disabled` 元素多数浏览器**不触发**、触屏无 hover、无法带快捷键徽标。这与你工具栏里 `:disabled="!canUndo"`（撤销/重做/分割等）的现状直接冲突——**用户最需要解释"为什么不能点"的时候，恰好没有任何提示**。

1. **写一个轻量 `FeTooltip` 组件**（~60 行，CSS + 一个 `provide/inject` 单例容器即可，不必引第三方库）：
   - **触发**：`pointerenter` 后 **420ms** 延时显示；`pointerleave` **立即**隐藏；`pointerdown` 立即隐藏；`Escape` 隐藏；
   - **位置**：默认**正下方居中**（`placement="bottom"`），工具栏在时间线顶部，下方空间充裕且不会遮住时间线内容；贴边时自动翻转到上方或左侧（用 `getBoundingClientRect()` 做 8px 边界避让）；
   - **样式**：`font-size: 12px; line-height: 1.4; padding: 5px 9px; border-radius: 6px; background: #10120f; border: 1px solid var(--fe-line-soft); box-shadow: 0 8px 20px rgba(0,0,0,.4); z-index: 60; max-width: 240px`——刻意用你现有的暗色 token，避免"系统浮层感"；
   - **内容结构**：`功能名` + `快捷键徽标`（`<kbd>` 样式：11px、`border-radius: 4px`、`background: rgba(255,255,255,.08)`），例如 `分割  Ctrl+B`；
   - **禁用态也显示**：把 tooltip 挂在 `wrapper` 上而不是按钮上（按钮 `disabled` 时 `pointer-events` 仍要在 wrapper 上生效），文案变成 `分割（请先选中一个片段）`。
2. **一次性替换全部 7 处 `title`，并给所有图标按钮补 tooltip**（这是可测的验收标准：`grep -c 'title="' src/views/FinalEdit.vue` 结果为 0）。
3. **给工具按钮加 `aria-keyshortcuts`**（如 `aria-keyshortcuts="Control+B"`），让 tooltip 与无障碍信息同源，避免两处维护键位。
4. **键位单一真源**：把快捷键表抽成 `src/constants/shortcuts.ts`（`{ id, label, keys, macKeys }`），tooltip、帮助弹窗、`keydown` 监听全部读它。这样"剪映式的版本漂移"在你的项目里不会发生。
5. **延迟不要做成 0**：悬停即弹会让长工具栏在快速划过时闪一串气泡。420ms 是"能显示但不闪"的平衡点；如果后续实测拖慢感，改到 300ms。

### 6.2 对自研工作台的可执行建议

**这是目前自研工作台与剪映差距最大的一块——草稿模型里根本没有叠加轨。**

1. **扩展草稿 DTO（向后兼容，不破坏现有 `videoClips`）**：
   ```ts
   export interface FinalEditVideoClipDTO {
     clipId?: string | null
     storyboardId: number
     enabled: boolean
     order: number                    // 同一 trackIndex 内排序
     trackIndex?: number              // 新增：0 = 主轨（默认），>=1 = 叠加轨/画中画
     videoAssetId?: number | null
     trimStartSeconds?: number | null
     trimEndSeconds?: number | null
     transform?: {                    // 新增：仅叠加轨有意义
       x: number; y: number           // 归一化 -1..1，0 = 居中
       scale: number                  // 1 = 铺满画布
       rotation: number               // 度
       opacity: number                // 0..1
       flipH?: boolean; flipV?: boolean
     } | null
     mask?: { type: 'none'|'linear'|'circle'|'rect'|'mirror'|'star'|'heart'|'pen'; feather: number; roundness?: number; invert?: boolean } | null
     blendMode?: 'normal'|'overlay'|'screen'|'multiply'|'soft-light'|string | null
     layerOrder?: number              // 新增：轨道相同时的仲裁，越大越靠上
     transition?: { type: 'cut'|'fade'|'dip'|'push'|string; durationSeconds: number } | null
   }
   ```
   - `trackIndex` 与 `order` **分工要写进注释**：`trackIndex` 决定合成层级，`order` 只在同一 `trackIndex` 内决定前后顺序。这直接对位剪映的"轨道上下 = 层级"语义，又避免了"主轨永远最底层 + 自由层级开关"这套复杂状态；
   - **迁移默认值**：读取旧草稿时 `trackIndex ?? 0`、`transform ?? null`，无需数据迁移脚本。
2. **画中画的创建方式（三选二，推荐 "拖拽 + 右键"）**：
   - **主推：把素材从素材库拖到主轨上方的一条轨道**——与剪映一致（剪映桌面版**没有**官方"画中画"按钮）。实现：鼠标 y 落在主轨行**上方 24px** 时，在 `videoTracks` 列表里插入一个新 `trackIndex`，并显示"新建叠加轨"提示线；
   - **补充：片段右键 →「转为画中画」**（一键把 `trackIndex: 0 → 1` 并设置默认 transform）。桌面端不建议做剪映手机版那种"画中画"大按钮，会污染主轨心智模型；
   - **不做**「主轨素材右键 → 新建复合片段 = 画中画」（剪映也没这么做）。
3. **画中画的默认 transform（关键决策，建议与剪映不同）**：
   - 剪映默认是**铺满并盖住主轨**（100% 缩放），新用户第一反应是"我的主轨没了"；
   - **建议默认 `scale = 0.34`、`x = 0.62`、`y = -0.62`（右下角）、`opacity = 1`、`rotation = 0`**，即"角标/解说框"尺寸（画布宽约 1/3，位于右下角）。这对漫剧成片尤其合适：**旁白解说框、角色特写插帧**是最常见用法。并在属性面板顶部显示一行提示「当前为角标尺寸，可拖拽预览区四角调整」。
   - 若担心与剪映习惯冲突：把它做成**项目级偏好**「新画中画默认：铺满 / 角标（推荐）」，默认"角标"。
4. **属性面板（画中画）参数清单**（照抄剪映的可用面，砍掉暂时无渲染管线的）：
   | 参数 | 控件 | 取值范围 |
   |---|---|---|
   | 位置 X / Y | 双 slider + 数字输入 | −1 ~ 1（归一化） |
   | 缩放 | slider | 0.05 ~ 3 |
   | 旋转 | slider | −180 ~ 180 |
   | 不透明度 | slider | 0 ~ 100% |
   | 翻转 | 两个 toggle | H / V |
   | 蒙版 | 下拉 + 羽化 + 圆角 | 8 种（对齐剪映，去掉"抠像"） |
   | 混合模式 | 下拉 | 先上 6 种：正常 / 叠加 / 滤色 / 正片叠底 / 柔光 / 相加 |
   | 层级 | 数字输入 | 1 ~ N（写 `layerOrder`） |
   每个数值参数右侧放**菱形关键帧按钮**（`P/S/R/T` 快捷打点），并高亮"当前值 ≠ 默认值"的行。
5. **时间线上的视觉表现（建议比剪映更明确）**：
   - 主轨行标签：`视频轨 0 · 主轨`，叠加行标签：`视频轨 1 · 画中画`；
   - 叠加轨每行**左侧 4px 强调色竖条**（不同 `trackIndex` 用不同明度），一眼区分层级；
   - 叠加片段块上**显示 `storyboardId + 变换摘要`**（如 `#12 · 34% 右下`），并在块内画一条与主轨不同的斜纹底，避免与主轨片段混淆（剪映是否显示标签未查到，此处为自研增强）；
   - 每行左侧加剪映同款的 **🔒 锁定 / 👁 隐藏** 两个图标（复用 `material-symbols-outlined` 的 `lock` / `visibility`），绑定到 `trackIndex` 级的 `locked` / `hidden` 状态。
6. **拖动换序 / 跨轨移动的规则（明确写死，避免歧义）**：
   - 同一 `trackIndex` 内水平拖动 = 改 `order`（**主轨开启"主轨磁吸"语义：松手后自动向前吸附、不留空隙**，剪映默认开启，这是防止"黑屏空白帧"的关键）；
   - 垂直拖过相邻轨道中线 = 改 `trackIndex`；**主轨的 `trackIndex` 不允许 > 0 为空**，即不允许把主轨最后一个片段拖到叠加轨后主轨变空——若发生，弹出确认或自动把相邻片段提升进主轨；
   - **跨轨移动时保留 `trimStart/trimEnd` 与 `enabled`**，但 `transform` 在进入 `trackIndex >= 1` 时写入默认值、退回 `trackIndex = 0` 时置 `null`（保证"主轨片段永远是全画幅"，与剪映"主轨永远最底层/无层级"一致）。
7. **转场约束照抄剪映的硬规则**：**只有同一轨道内相邻的两个片段之间才允许加转场**（剪映独有设置），跨轨不加。同时处理剪映明确踩过的坑——**转场"重复帧"**：剪映用两个素材首尾帧做转场，未裁剪时两端是静止画面从而出现重复帧，用户需手动裁剪两端来消除。**建议在自研里从模型层避免**：`transition.durationSeconds` 从两个片段各自的内侧「借」时长（渲染时前段末尾 `duration` 秒与后段开头 `duration` 秒做交叉溶解），**不产生静止重复帧**，并在属性面板显示「转场将占用前段末尾 0.5s」的说明。
   （重复帧问题出处：`[教程]` [blog.csdn.net/cwtlw/article/details/147387939](https://blog.csdn.net/cwtlw/article/details/147387939)）

**（3）拖动播放头时是否出现文字重影/描边等渲染问题——`未查到任何官方或社区说法`。**
我专门检索了「播放头 拖动 卡顿 / 文字 重影 / 描边 / 闪烁」等组合，可获取到的只有两类相关信息：
- 剪映的**转场重复帧**问题（与播放头渲染无关，见 6.2 第 7 条）；
- 剪映基于 **C++/Skia 类自绘 UI 渲染**，其 GPU 合成管线与浏览器 DOM 渲染是两套机制，**用剪映的实现方式反推 Web 实现并不成立**。
→ **本节关于"重影/描边"的成因与规避方案，全部是 `[推断]`。**

### 7.2 自研工作台的现状证据（这是本节最有价值的部分）

在 `src/views/FinalEdit.vue` 里可以直接读到：

```ts
// 播放头位置：用 left 定位（触发布局）
const timelinePlayheadStyle = computed(() => ({
  left: `${122 + timelinePositionSeconds.value * timelinePixelsPerSecond.value}px`,
}))
```
```css
.fe-timeline-playhead { position: absolute; top: 0; bottom: 0; z-index: 10; width: 0; }
.fe-edit-overlays      { position: absolute; inset: 0; pointer-events: none; z-index: 3; }
.fe-edit-lane { position: relative; min-height: 38px; overflow: hidden; }
```
以及刻度与轨道宽度都是**响应式绑定的 px 宽度**（`timelineCanvasWidthPx` / `timelineTrackWidthPx`）。

**技术判断（`[推断]`）**：
1. **`left` 是布局属性**——每帧改 `left` 都会让播放头所在层重新参与 Layout，再走 Paint/Composite；在 60fps 拖动下，配合 Vue 的响应式更新，**在片段多、轨道多、字幕多的草稿上很容易掉帧**，视觉表现就是竖线"拖尾"、片段块边缘抖动、文字层出现**重影/描边感**（本质是相邻两帧的半透明内容被连续绘制在同一视觉位置）。**这正是用户所说"文字重影/描边"最可能的成因：不是文字本身的问题，而是跟随播放头重绘的整层内容在帧间不稳定。**
2. 视频元素在拖动过程中被反复 `seek` 时，解码器会输出不完整/重复帧，与上一条叠加，会加重"重影"观感。

### 7.3 对自研工作台的可执行建议

**A. 播放头吸附（先定规则，再做手感）**
1. **阈值**：**8 CSS px**（屏幕像素域，不用时间域）；按住 `Alt` 时**临时禁用吸附**（与剪映"按住 Ctrl 取消播放器对齐"的思路一致，但绑 `Alt` 避免与浏览器缩放冲突）。
2. **吸附目标与优先级**（命中即停，只取最近的一个）：
   `① 当前选中片段的 start / end` → `② 所有片段边界（含其他轨）` → `③ subtitleCues 的 start / end`（漫剧对口型最关键）→ `④ beatMarkers`（卡点）→ `⑤ emotionCurve` 标注点 → `⑥ 整秒/整 5 秒刻度`。
3. **反馈**：吸附命中时竖线由 1px 变 2px、颜色由 `var(--fe-muted)` 变 `var(--fe-accent)`，并在刻度行显示目标标签（`吸附：字幕 3 起点 00:12.480`）。松手后 400ms 内标签淡出。
4. **吸附开关**：工具栏已有 `timelineSnapEnabled`（`magnet` 图标），把它从"只影响片段"扩展为"同时影响播放头"，并在 tooltip 里写明范围（`吸附：片段 / 播放头 / 节拍点`）。
5. **播放头拖动时的预览刷新策略**（防止"边拖边 seek"把解码器打爆）：
   - 拖动中（`pointermove`）只更新**时间码 + 吸附指示 + 一个轻量的"拖动预览层"**，用 rAF 节流（每次只保留最新一帧，`pendingX` 覆盖写）；
   - **不要每帧 `video.currentTime = t`**。改为：拖动中显示**最近关键帧抽帧图**（`<video>` 的 `poster` 或预先打好的缩略图条），松手（`pointerup`）后做 1 次精确 `seek`；这既解决重影，也解决拖动卡顿；
   - 若必须实时预览，把 seek 节流到**≥66ms（15fps）**，并在拖动期间给播放器加 `filter: none`、关闭任何 CSS 滤镜/阴影。

**B. 渲染细节（把"重影/描边"从根上掐掉）**
1. **播放头改用 transform 定位**（最高优先级，1 行改动）：
   ```ts
   const timelinePlayheadStyle = computed(() => ({
     transform: `translate3d(${122 + timelinePositionSeconds.value * timelinePixelsPerSecond.value}px, 0, 0)`,
   }))
   ```
   ```css
   .fe-timeline-playhead {
     position: absolute; top: 0; bottom: 0; left: 0; width: 0;
     will-change: transform;          /* 提升为合成层 */
     transform: translate3d(0,0,0);
     contain: layout style paint;     /* 把重排/重绘锁在自己的子树里 */
     pointer-events: none;
   }
   ```
   注意：**`will-change` 只在拖动期间加**（`pointerdown` 加、`pointerup` 后 300ms 移除），常驻会白占显存。
2. **文字层与字幕层加隔离，避免与播放头层互相影响**：
   ```css
   .fe-edit-clip-label, .fe-beat-marker, .fe-preview-subtitles {
     isolation: isolate;              /* 新建层叠上下文，防止混合/滤镜外溢 */
     transform: translateZ(0);
     backface-visibility: hidden;
     user-select: none;               /* 拖动中禁用文字选择，消除选区高亮伪影 */
     -webkit-user-select: none;
   }
   ```
   `user-select: none` 尤其重要：拖动播放头时鼠标会扫过片段的文字标签，触发文本选区，视觉上非常像"文字重影/描边"。
3. **统一承载层，避免兄弟层互相重绘**：把播放头放进独立的 `.fe-timeline-playhead-layer`（`position: absolute; inset: 0; pointer-events: none; z-index: 10; contain: strict;`），与 `.fe-edit-overlays`（现有 `z-index: 3`）分离——**层级不要混在一个容器里**，否则播放头移动会让节拍标记、情绪曲线一起重绘。
4. **刻度尺用 `sticky` 已经是好设计**（现 `.fe-edit-ruler` 已有 `position: sticky; z-index: 12`），但要给它 `contain: content` 并把刻度文案放在 `aria-hidden` 的伪元素里，减少文本重排。
5. **拖动期间冻结"昂贵视觉"**：给时间线根节点加 `.is-dragging` 类，用 CSS 一次性关掉 `box-shadow`、`backdrop-filter`、渐变背景、`transition`——这些是拖动掉帧最常见的元凶：
   ```css
   .fe-edit-timeline.is-dragging * { transition: none !important; box-shadow: none !important; backdrop-filter: none !important; }
   .fe-edit-timeline.is-dragging .fe-edit-lane { background-image: none; }
   ```
6. **数据侧只让一个数字变化**：把 `timelinePositionSeconds` 保持为**单一 `ref<number>`**，拖动中直接写它（不要顺手 `computed` 出一堆派生对象触发整棵子树更新）；片段/字幕的"当前是否高亮"用 CSS 变量或 `:class` 绑定在**最小粒度**上（每个 clip 自己判断），不要让父组件整表重渲。
7. **验收标准（可测）**：
   - 打开 Chrome DevTools → Performance 录制"连续拖动播放头 5 秒"，要求 **无长任务 > 50ms、Layout 次数 ≤ 5 次/秒**；
   - Rendering 面板勾选 `Paint flashing`，拖动时**只有播放头所在的窄条区域闪烁**，片段块与文字标签区域不应闪；
   - 在高 DPI（150%）+ 60 个分镜 + 30 条字幕的草稿上拖动，肉眼无拖尾、无文字重影。

**P2（一个月）**
