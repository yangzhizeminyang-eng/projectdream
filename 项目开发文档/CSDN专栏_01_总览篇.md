# 帧心帧意 ProjectDream：从项目到成片的 AI 漫剧工作台

> 这篇是整个专栏的总览。不是讲概念，也不是堆术语，主要说清楚一件事：这个项目到底是怎么把“一个想法”一步步做成“能导出的成片”的。

## 先说结论

ProjectDream 做的不是一个单点生成工具，而是一套完整的 AI 漫剧生产工作台。

它把一条很长的链路串了起来：

项目创建 -> 故事总纲 -> 场景拆解 -> 单场剧本 -> 角色库 -> 分镜 -> 静帧 -> 视频 -> 音频 -> 成片编辑 -> 导出

如果只看 demo，这些模块都像“能点开的页面”。但真正把它们连起来之后，项目的味道就出来了：前面做的内容，后面能接得上；后面改了，前面也不会完全脱节。

## 这个项目解决什么问题

我一开始做这个项目时，目标其实很直接。

不是想做一个“会生成图”的网站，而是想做一个能把 AI 内容生产真正串起来的工作台。因为只要你真做过一次短视频或漫剧流程，就会发现最费劲的不是生成本身，而是这些中间环节：

- 文本和画面不一致
- 角色前后长相漂移
- 分镜一多就乱
- 音频和镜头对不齐
- 导出时又冒出一堆历史残留素材

这些问题单拎出来都不难，难的是它们会一起出现。

所以 ProjectDream 的思路不是“让 AI 一口气生成完”，而是把每一步都做成可确认、可回跳、可重试的状态。这样项目就不是一个黑盒，而是一条能手工接管的生产线。

## 我最后做成了什么

现在这个项目已经跑通了一条完整闭环：

- 登录注册
- 项目总览和新建项目
- 总纲、场景、剧本生成
- 角色库和角色一致性
- 分镜生成与编辑
- 静帧生成与确认
- 视频生成与口型同步
- 音频生成与声线绑定
- 任务中心
- 成片编辑
- FFmpeg 导出

比较重要的是，它不是“页面都在，但流程断着”的那种 demo。后台任务、素材落库、导出校验、媒体下载、任务恢复这些东西都已经接上了。也就是说，页面不是摆设，是真能把内容往下推的。

## 技术上怎么搭的

这套项目的前后端分得很清楚。

前端是 Vue 3 + TypeScript + Vite + Vue Router + Pinia + Tailwind CSS。页面不算少，但结构还算干净，基本是“一类工作流对应一组页面”。

后端是 Node.js 原生 HTTP 服务，不是 Express。主入口是一个大文件 `server/index.mjs`，里面负责路由分发、数据库初始化、任务状态流转和媒体导出。真正比较重的业务逻辑，会拆到 `server/services/` 里。

数据库用的是 MySQL。生成出来的图片、视频、音频、导出文件，先落到本地 `.codex-runtime/`，这样开发和演示的时候能跑通整条链路。

AI 这边接了三类能力：

- 文本：OpenAI-compatible 接口
- 图片和视频：Agnes
- 音频：DashScope TTS

这样拆的好处很明显。文本、图像、视频、语音不是同一个供应商时，也能把整条链路接起来，不会卡在单点上。

## 页面大概长什么样

这个项目的页面不是传统“看介绍页”的那种结构，而是直接围绕工作流来做。

登录后先到项目总览，再进入具体模块。左侧是工作台导航，顶部是项目切换和模型设置。每个页面都尽量只干一件事，比如：

- `AIScript.vue` 负责总纲和剧本
- `CharacterLibrary.vue` 负责角色库
- `StoryboardEditor.vue` 负责分镜编辑
- `FrameGenerate.vue` 负责静帧生成
- `VideoGenerate.vue` 负责视频生成
- `AudioStudio.vue` 负责音频
- `FinalEdit.vue` 负责成片草稿
- `Export.vue` 负责导出

这种拆法的好处是，发文章的时候也很好讲：每个模块都能单独成篇，但放在一起又是一条完整链路。

## 我最想放在总览里讲的三件事

### 1. 角色不会轻易跑偏

这项目不是简单生成一张角色图就结束了。角色有档案、定妆图、声线、年龄段、性别和外貌描述，后面的分镜和静帧都会尽量沿着这些信息走。

这一步很关键。因为做漫剧最烦的就是“上一张还是这个人，下一张就不像了”。我后来基本是把“角色一致性”当成一条独立链路来做的，而不是附属功能。

### 2. 任务不是同步卡死，而是后台慢慢跑

图片、视频、口型同步这类任务，我没有做成前端一直等结果的模式，而是让它们进任务中心。

用户提交后可以先去别的页面，服务端自己继续跑。这个设计很朴素，但实用，尤其适合本地开发、演示和小规模试产。

### 3. 导出不是拼一段视频那么简单

最后导出的那一步，其实是整个项目里最容易出问题的地方。

因为导出的时候要管：

- 哪些镜头启用
- 哪些是确认过的主版本
- 哪些音频要保留
- 哪些旧内容要跳过
- 字幕怎么烧
- 视频和音频时长怎么对齐

我最后是用 FFmpeg 把这些东西串起来的。这样做不算轻，但稳。

## 这套项目的真实边界

说实话，这个项目还不是那种可以直接拿去大规模生产的系统。

它现在更像一个已经跑通的可用原型，离正式生产还有几件事要补：

- 生成媒体最好迁到对象存储
- 后台任务最好独立成 worker
- `server/index.mjs` 这种大文件后面还是得拆
- 任务中心后面可以补实时推送

但这不影响它现在已经能做成一个很完整的演示项目。对博客来说，这反而是好事，因为它不是空想架构，而是有真实链路、有真实截图、有真实测试结果的。

## 适合放在文末的小结

ProjectDream 这次最有价值的地方，不是单独某个页面做得多花，而是它真的把“内容生产”这条链路接起来了。

从故事到角色，从分镜到素材，再到最后的成片导出，整个过程能跑通，能回跳，能确认，也能重试。对一个 AI 漫剧工作台来说，这比“能生成一张图”要重要得多。
