# 第一集 Agnes 混合路线试制与人工验收开发流程

## 1. 目标

本流程用于项目 12《零点回声》第一集的受控试制。第一阶段不直接复制生产第二集、第三集，而是先用一集验证以下链路是否可复用：

```text
角色 v7 + image_asset #325
  -> Agnes 图片
  -> Agnes 动作视频
  -> 项目现有 TTS/对白音频
  -> 口型同步
  -> 字幕与混音
  -> 竖屏终剪
  -> 自动技术质检
  -> 人工完整播放
```

本流程的“完成”只代表第一集试制成片完成并具备人工验收入口，不代表已经通过平台审核、可以稳定发布或已经产生稳定收入。

## 2. 范围与固定约束

### 2.1 角色与参考资产

- 项目：`projectId=12`
- 主角色：林夏，角色版本 `v7`
- 统一参考图：`image_asset #325`
- 参考图对象：`projects/12/frames/storyboards/267/v1/c1.jpg`
- 生产过程中不得自动回退到旧角色版本，也不得混用未确认的角色参考图。

### 2.2 第一阶段镜头规模

- 核心分镜：9 条，位于第一集约定的 6 至 10 条核心镜头范围内。
- 每条核心镜头都必须有明确的 `storyboardId`、画面提示、动作节拍、对白或旁白归属、时长和素材来源。
- 广播机空镜、旁白和实体角色对白分开处理，不能把广播旁白错误绑定到未定妆角色。

### 2.3 受控执行原则

- 默认只执行约定的第一集核心分镜。
- 支持 `--only=<storyboardId>` 单条重跑。
- 支持 `--dry-run` 只验证配置和任务边界。
- 支持 `--skip-export`、`--export-only` 分阶段验证。
- 导出 Worker 必须能用 `EXPORT_WORKER_ONLY_EXPORT_ID=<exportId>` 限定单条导出。
- 任何失败都保留任务、资产和导出记录，不用静音或模拟媒体伪造成功。

## 3. 生产流程

### 3.1 生产前检查

1. 检查项目 12 的故事圣经和整季结构仍为锁定状态。
2. 检查林夏当前激活角色版本为 `v7`。
3. 检查 `image_asset #325` 的 COS 对象可读。
4. 检查 Agnes 图片、Agnes 视频、TTS、口型同步和 COS 配置。
5. 检查目标分镜属于第一集核心清单，禁止越界批量执行。
6. 检查已有对白音频必须有文本快照，不能盲目复用旧音频。

### 3.2 Agnes 图片阶段

1. 为每个核心镜头生成一张 Agnes 静帧候选。
2. 请求必须携带 `image_asset #325` 作为参考图。
3. 角色提示必须同时包含脸部、发型、服装、体型和不新增人物约束。
4. 任务完成后保存：
   - `image_asset.id`
   - `storage_key`
   - 供应商模型和实际回退模型
   - `generation_job.id`
   - 角色快照和版本证据
5. 静帧任务失败时只允许重试指定分镜，不得顺手重跑整集。

### 3.3 Agnes 动作视频阶段

1. 以通过确认的静帧作为输入生成动作视频。
2. 动作提示使用分镜的 `actingBeat`、起始画面和结束画面约束。
3. 对白镜头只允许绑定对应分镜的实体角色；广播、电话、画外音使用旁白音轨。
4. 视频资产保存输入静帧、角色版本、生成任务和 COS 对象证据。
5. 视频完成后先做帧率、分辨率、时长和对象可读性检查，再进入口型同步。

### 3.4 TTS 与音轨阶段

1. TTS 文本来自当前分镜的有效文本快照。
2. 对白音频需要记录：
   - `audioAsset.id`
   - `storyboardId`
   - `trackType`
   - `characterId`
   - `characterVersionNo`
   - `storageKey`
   - 文本快照
3. 同一分镜的口型视频和终剪对白必须引用同一个已确认 `audioAsset`。
4. 不允许把历史公网地址当作唯一源地址；优先从 `storageKey` 读取 COS 对象。

### 3.5 口型同步阶段

1. 对白镜头调用口型同步，输入为 Agnes 动作视频和对应 TTS 音频。
2. 口型同步结果保存音频同源绑定证据。
3. 终剪混音不能替换口型生成时使用的对白源。
4. 自动检查只验证来源、时钟和技术可读性，不把音频波形相似当作真实嘴型自然。

### 3.6 字幕、混音和终剪阶段

1. 依据音轨和分镜时间轴生成字幕 cue。
2. 字幕必须烧录到成片，同时保留独立 `subtitles.srt`。
3. 字幕必须处于竖屏平台安全区，避免底部操作区遮挡。
4. 混音统一输出：
   - `H.264`
   - `AAC`
   - `1080x1920`
   - `24fps`
   - `48kHz`
   - MP4
5. 对白、旁白和环境声使用独立轨道，避免广播旁白覆盖实体角色对白。
6. 导出后保留源片段、字幕、音频、配置快照和最终 MP4。

## 5. 自动技术质检门禁

自动门禁至少检查：

1. 画面规格、帧率、时长和编码器。
2. 黑边、冻结帧和跳帧风险代理。
3. 字幕是否烧录、文字数量和时间轴。
4. 字幕安全区像素探针。
5. 音频采样率、声道、综合响度、真峰值、削波和静音风险。
6. 口型视频对白音频是否与终剪同源。
7. 角色版本和参考图证据是否存在。
8. 成片对象是否能从 COS 读取。

自动门禁通过条件是技术证据完整且没有阻塞项；它不判断：

- 声音是否像真人自然说话；
- 嘴型是否与汉语发音逐字自然同步；
- 情绪是否达到市场爆款水平；
- 人物动作是否让观众觉得真实；
- 平台是否接受投稿；
- 成片是否能稳定赚钱。

## 6. 人工完整播放验收

人工审核必须在导出页选择 `export #61`，从头播放到结尾，并单独记录：

### 6.1 画面

- 是否拉伸、黑边、跳帧或明显卡顿；
- Agnes 动作是否过于僵硬；
- 镜头切换是否突兀；
- 人物脸部、服装、体型和动作是否保持一致；
- 开头 1 至 3 秒是否能形成异常事件或追看理由。

### 6.2 字幕

- 文字是否与实际对白一致；
- 时间轴是否早出、晚出或跨镜头；
- 字体、描边和字号是否清楚；
- 是否被红果、抖音底部区域遮挡；
- 广播、旁白和人物对白是否能区分。

### 6.3 音频和口型

- 是否实际播放到结尾；
- 对白是否清晰；
- 响度是否平衡；
- 是否出现爆音、失真、底噪或突然静音；
- 对白是否与嘴型自然同步；
- 情绪、停顿、重音是否匹配画面；
- “妈”“五”等关键字是否由正确角色说出。

### 6.4 发布合规

- 是否有 AI 标识；
- 是否拥有小说、角色、画面、声音和音乐的使用权；
- 红果、抖音目标字段是否分别完成证据记录；
- 不把内部技术质检通过写成平台审核通过。

人工结果只能保存为：

```text
approved
rework
```

没有完整播放和结构化证据时，必须保持 `blocked` 或 `rework`。

## 7. 复制到第二、第三集的准入条件

第一集通过人工复核后，才允许复制生产模板。准入条件：

1. `export #61` 技术报告通过。
2. 人工完整播放证据齐全。
3. 画面、字幕、音频、人物一致性四类证据齐全。
4. 关键对白与嘴型没有明确错位。
5. 角色 v7 和 `image_asset #325` 的使用约束没有被绕过。
6. 第一集至少完成一次返工闭环或确认不需要返工。
7. 第二集和第三集仍按单集、单条、可回滚方式执行，不直接批量调用模型。

## 8. 故障处理

| 故障 | 处理 |
| --- | --- |
| 图片任务排队 | 先检查 Worker，不直接重复点生成 |
| Agnes 模型不可用 | 记录实际回退模型，不伪装为目标模型 |
| COS 对象 404 | 按 storageKey 修复或单条重生成，不复用未知历史音频 |
| 口型音频错源 | 阻断终剪，重新绑定同一 audioAsset |
| 字幕缺失 | 阻断人工批准，重新生成字幕和终剪 |
| 人物版本证据缺失 | 阻断发布候选，补齐版本快照 |
| 人工听感不通过 | 标记 rework，保留原成片和返工原因 |

## 10. 结论

第一集的机器生产链路已经跑通，`export #61` 是当前人工审核入口。下一步不是直接复制第二集，而是由小泽完整播放第一集并反馈：画面、字幕、音频、口型、情绪和人物一致性。只有反馈闭环通过，才把该模板用于第二集和第三集。
